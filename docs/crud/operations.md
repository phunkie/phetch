# CRUD Operations

All functions live in `Phunkie\Phetch\Functions` and return a `Query`; see [Queries](../core/queries.md) for how to run one.

```php
use function Phunkie\Phetch\Functions\{find, findOrFail, findBy, findOrCreate, all, create, insert, update, remove, where};
```

## Reading

| Function | Returns | Notes |
|---|---|---|
| `find(User::class, $id)` | `Query<Option<User>>` | by primary key |
| `findOrFail(User::class, $id)` | `Query<User>` | fails with `RowNotFound` |
| `findBy(User::class, 'email', $email)` | `Query<Option<User>>` | first row with that column value |
| `all(User::class)` | `QueryBuilder`, a `Query<ImmList<User>>` | every row, or a starting point for the [builder](../querying/builder.md) |
| `where(User::class, 'active', true)` | `QueryBuilder` | the builder with one criterion |

```php
find(User::class, 1)->run($conn)->flatMap(fn(Option $user) => $user->fold(
    io(fn() => 'nobody'),
    fn(User $found) => io(fn() => $found->name),
));

findOrFail(User::class, 1)->run($conn)->map(fn(User $user) => $user->name);
```

Prefer `findOrFail` when a missing row is an error for the caller, `find` when it is a case to handle.

## Writing

| Function | Returns | Notes |
|---|---|---|
| `create(User::class, $data)` | `Query<User>` | inserts, then reads the row back by its generated key |
| `insert(BookTag::class, $data)` | `Query<int>` | inserts without reading back, for rows with no generated key; yields the rows written |
| `findOrCreate(Tag::class, $by)` | `Query<Tag>` | the row matching every column in `$by`, created from them when there is none |
| `update(User::class, $id, $data)` | `Query<Option<User>>` | `None` when the id is unknown |
| `remove(User::class, $id)` | `Query<bool>` | `true` when a row was deleted |

`$data` and `$by` are arrays keyed by constructor parameter name or by column name; see [Models](../core/models.md) for how names and typed values are written.

```php
create(Book::class, ['authorId' => 1, 'title' => 'Notes', 'publishedOn' => new DateTimeImmutable('1843-09-01')]);
update(Book::class, 1, ['title' => 'Notes on the Analytical Engine']);
findOrCreate(Tag::class, ['name' => 'maths']);
remove(Book::class, 1);
```

`update` with an empty array throws `InvalidArgumentException` when built. `create` on a model whose key is not generated by the database, such as a link table, reads back nothing useful; use `insert`.

## Safety

- Values are bound as prepared-statement parameters, always.
- Table and column names must match `[A-Za-z_][A-Za-z0-9_]*` and are quoted for the driver. A key of `$data` that is not a constructor parameter is taken as a column name and validated the same way, so an unfiltered request body cannot reach a query as column names. On the http4p side, `decode($req, Model::class)` only yields the model's own parameters.
- The database's own refusals, a duplicate key or a missing foreign row, surface as `ConstraintViolation`; see [Errors and Transactions](../core/errors-and-transactions.md).

## Raw SQL

There is no raw query function. For what the builder cannot express, use `Connection::pdo()` inside a `Query`, as migrations do:

```php
new Query(fn(Connection $conn) => io(fn() => $conn->pdo()->query('SELECT COUNT(*) FROM books WHERE price > 10')->fetchColumn()));
```
